How to upload product photos in Sanity

For CLARO-PROM catalogue editors. The V2 field grouping and captions are available in the reviewed Preview; production receives them only after a separately approved release.

Preview and production use the same Sanity production dataset. Saving changes creates real drafts; Publish changes the public website. During V2 review, do not upload, replace or publish test images. Use only approved real product photos in normal catalogue maintenance.
  1. Open Sanity Studio and sign in with your authorized account.
  2. Choose Products → English (or the correct document language), then find the exact product. Check its catalogue number and packaging before selecting a photo. Do not change the URL or classification.
  3. In Photographs, open Main product photograph. Use Upload to add a real photo, or Replace to change the existing one. Field controls may appear in the image menu.
  4. Enter Alternative text describing only what is visible, for example “CLARO-PROM Claroclear Xylene Substitute, 1 L bottle, front view.” Match the record language. If empty, the website uses the product name.
  5. Use Photograph caption only when clarification is needed. Example: “Representative 1 L pack; this catalogue record is supplied in 10 L.” Prefer a correct SKU photograph; leave empty rather than show an unexplained wrong pack.
  6. Add actual Additional photographs: rear view, label detail or another relevant angle. Give each an alt description and, where useful, a caption.
  7. Drag gallery entries into the intended order. The website preserves this order and loads additional views lazily.
  8. Review the draft in Presentation when your account and preview access permit. Confirm the correct product, actual packaging, label visibility, image proportions and mobile view. Opening Preview does not isolate the dataset. The public-page link shows the published version.
  9. Only after the responsible reviewer approves the real change, click Publish. Existing published data remains active before publication.
  10. Open the public product URL, reload and verify the correct image and alt text. Live-content revalidation is configured; if content seems stale, allow refresh and check the exact record.
  11. If wrong, replace it with the last approved image or remove it and republish after review. Existing assets can be selected again from the asset library. Do not delete an asset used elsewhere.

Practical photography recommendations

Use a square or near-square canvas as a convenient default; portrait bottles and wide boxes are also supported. Aim for 1600–2400 px on the longest edge, at least about 1200 px when available. JPEG or WebP suits packshots; PNG suits a genuinely transparent background. Usually 0.5–3 MB is practical; keep label detail readable without uploading needlessly large files. These are recommendations, not blocking validation rules.

Keep the whole bottle, cap, handle, canister or box visible, with a small margin and a neutral light background. Use consistent lighting. The web display uses object-contain with responsive image optimization; it does not force packshots into a destructive square crop. The image editor’s explicit Crop removes pixels: keep it conservative and inspect the label. Hotspot is available for views that crop; contained packshots keep the entire selected crop.

What is supported

Existing main-photo upload/replacement, gallery ordering, alt text, crop/hotspot and Sanity CDN remain. V2 adds clear photo grouping, field instructions, optional captions, smaller responsive CDN images and no empty image block. No duplicate image fields or new required fields are added.

Short description is a separate approved summary in the language of the product document. It is not intended purpose and does not update SEO metadata. Do not copy proposed review text into the public catalogue until approved.

Verification limitation: authenticated upload, replacement and Publish were not tested in V2 because there is no confirmed isolated dataset. Existing images and isolated render fixtures are tested without CMS writes.
